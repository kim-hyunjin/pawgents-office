# Pawgents Office

Claude Code 세션들이 일하는 모습을 **픽셀아트 사무실**로 보여주는 로컬 웹 UI입니다.

- 터미널에서 띄운 `claude` 세션 하나 = 직원 한 명. 책상에 앉아 파일을 읽고, 코드를 고치고, 터미널을 두드립니다.
- `Agent` 툴로 띄운 서브에이전트 = 옆자리 보조 직원. 일이 끝나면 사라집니다.
- 권한 승인을 기다리면 손을 들고 `!`, 답변이 끝나면 말풍선, 세션이 끝나면 문으로 퇴근합니다.
- 직원을 클릭하면 오른쪽 패널에 활동 로그가 나옵니다. 패널의 답변 카드를 누르면 전체 답변을 마크다운으로 크게 볼 수 있고, 작업한 파일을 누르면 그 파일의 git diff가 열립니다.

[Bun](https://bun.sh) 1.4 이상이 있으면 됩니다(훅과 서버를 `bun`으로 실행하므로 PATH에 있어야 합니다). 서버·훅은 런타임 의존성이 없고, 브라우저 화면은 [Preact](https://preactjs.com)를 esm.sh에서 불러오므로 인터넷 연결이 필요합니다(`web/index.html`의 import map, 버전은 `package.json`과 같게 고정). 전체가 TypeScript이고 빌드 단계는 없습니다(서버가 `web/*.ts`·`*.tsx`를 요청 때 변환해 내려줍니다).

## 사용법

### Claude Code 플러그인으로 (권장)

```
/plugin marketplace add kim-hyunjin/pawgents-office
/plugin install pawgents-office@pawgents-office
```

설치 후 새로 띄우는 `claude` 세션부터 훅이 자동으로 걸리고, 세션이 시작될 때 서버가 꺼져 있으면 백그라운드로 띄웁니다(로그: `~/.pawgents-office/server.log`). settings.json은 건드리지 않습니다.

| 명령 | 동작 |
|---|---|
| `/pawgents-office:open` | 서버를 (꺼져 있으면) 띄우고 브라우저로 http://127.0.0.1:17777 을 엽니다 |
| `/pawgents-office:stop` | 백그라운드 서버를 끕니다 |

자동 시작이 싫으면 `PAWGENTS_OFFICE_AUTOSTART=0`을 설정하고 `bun run start`로 직접 띄우세요.
예전에 `bun run install-hooks`로 훅을 설치했다면 이벤트가 두 번 들어가니 `bun run uninstall-hooks`로 먼저 지우세요.
로컬 클론을 그대로 쓰려면 `/plugin marketplace add ~/pawgents-office` 처럼 경로를 넣으면 됩니다.

### 직접 실행

```bash
cd ~/pawgents-office
bun run install-hooks     # 최초 1회: ~/.claude/settings.json에 hook 등록 (자동 백업)
bun run start             # http://127.0.0.1:17777
claude                 # 아무 터미널, 아무 레포에서 평소처럼 사용
```

```bash
bun run demo              # Claude 없이 가짜 직원 2명으로 화면 확인
bun run uninstall-hooks   # hook 제거 (settings.json 원복)
bun run test          # bun test: 모듈별 단위 테스트 + HTTP·상태 동작 고정 테스트 + 의존 규칙 검사
bun run typecheck     # tsc --noEmit (strict) + 웹 전용(DOM만) 타입 검사
bun run lint          # biome check: 린트 + 포맷 + import 정렬 검사
bun run format        # biome check --write: 포맷과 import 정렬, 안전한 수정을 적용
```

`bun server/index.ts`, `bun hooks/install.ts` 처럼 직접 실행해도 됩니다.

## 동작 방식

| 소스 | 용도 |
|---|---|
| **Claude Code hooks** (`SessionStart/End`, `UserPromptSubmit`, `Pre/PostToolUse`, `PermissionRequest`, `Notification`, `Stop`, `SubagentStart/Stop` 등) | 상태 변화의 주 소스. `async` command hook이라 Claude를 기다리게 하지 않고, 훅 스크립트는 아무것도 출력하지 않아 **토큰을 쓰지 않습니다**. |
| `~/.claude/sessions/<pid>.json` | 살아있는 세션 목록. hook 설치 전에 시작된 세션도 여기서 잡아 표시합니다(존재·바쁨 여부만). 프로세스가 죽으면 퇴근 처리. Windows에서는 죽은 세션의 PID를 다른 프로세스가 물려받아도 파일의 `procStart`(프로세스 시작 시각)로 구분합니다. |
| transcript (`~/.claude/projects/.../<session>.jsonl`) | 세션 제목, 모델, 최근 답변 텍스트(말풍선). 상태는 바꾸지 않습니다. |
| `git status` / `git diff` (세션의 작업 폴더) | 패널의 작업한 파일 목록과 파일 diff. 훅 없이 시작한 세션이나 서버 재시작 뒤에도 변경 파일이 보입니다. |

서버(`server/`)는 `POST /hook`으로 이벤트를 받아 상태를 갱신하고 `GET /events`(SSE)로 브라우저에 밀어줍니다.
책상 배정은 `~/.pawgents-office/state.json`에 기억되어 서버를 재시작해도 같은 세션은 같은 자리에 앉습니다.

## 사무실 구조와 행동

기본 배치는 방 종류마다 하나씩 있는 아래 모양입니다. 배치는 사무실마다 [배치 편집](#배치-편집)으로 바꿀 수 있습니다.

```
┌ 회의실 ┐┌─ 사무 공간: 2인 책상 6개 (12석) ─┐┌ 서재 (책장) ┐
└────────┘└──────────────────────────────────┘└─────────────┘
  복도
┌ 로비 ┐┌ 라운지 ┐┌ 기획실 (화이트보드) ┐┌ 놀이터: 캣타워·스크래처·캣휠·털실·상자·방석 ┐
└─입구─┘└────────┘└─────────────────────┘└───────────────────────────────────────────┘
```

고양이가 가는 곳은 방 종류가 아니라 **가구**로 정해집니다. 방 종류는 바닥 색과 이름표만 바꾸므로, 예를 들어 화이트보드를 라운지에 두면 `plan` 모드 고양이는 라운지의 그 보드 앞으로 갑니다. 같은 가구가 여러 개면 자리를 함께 쓰고, 그 가구가 하나도 없으면 해당 행동은 건너뛰고 자리에 머뭅니다.

| 상황 | 행동 |
|---|---|
| 새 세션 | 정문으로 들어와 빈 책상까지 걸어감 (벽·가구를 피해 경로 탐색). 책상이 모자라면 로비에서 대기 |
| 서브에이전트가 살아 있음 | 직원이 빈 **회의 테이블** 상석에 앉고, 보조 직원들이 테이블에 둘러앉음(노트북 펼침). 마지막 보조가 끝나고 8초 뒤 복귀. 회의 테이블이 다 차면 책상 옆 통로에 보조 직원이 서서 일함 |
| `plan` 모드 | **화이트보드** 앞에 서서 마커로 끄적임. 모드가 바뀌면 자리로 복귀 |
| 웹 검색 (WebFetch / WebSearch) | **책장** 앞에 서서 책을 뒤적임. 마지막 검색 후 10초 동안 머물다 자리로 복귀(연속 검색 시 왔다갔다 방지), 대기 상태가 되면 바로 복귀 |
| `auto` / `bypassPermissions` / `dontAsk` | 번개 배지, 타이핑과 모니터 코드 스크롤이 빨라짐 |
| `acceptEdits` | 체크 배지 |
| 15초 이상 대기 | 자리를 떠나 놀이 가구와 휴식 가구 사이를 돌아다님: 캣타워 꼭대기, 스크래처에 앞발 대고 긁기, 캣휠 달리기, 털실 치기, 상자에 들어가기, 방석에서 낮잠(Zzz), 소파·커피 머신, 놀이터 윗줄에서 구경. 7~15초(낮잠·소파·커피는 20~40초)마다 다른 곳으로 이동. 다음 프롬프트에 복귀 (`?playAfter=초` 로 조절). 백그라운드 셸을 기다리는 중이면 자리에서 대기 |
| 권한 대기 | 손 들고 `!` |
| 세션 종료 | 문으로 걸어 나가고 5분 뒤 책상 반납 |

이름·상태 글자는 화면에 띄우지 않습니다. 고양이에 마우스를 올리면 툴팁, 클릭하면 상세 패널이 열립니다. 왼쪽 위 상태 표시의 "목록 ▾"를 누르면 직원 목록이 열려, 모두의 상태·위치를 한눈에 보고 줄을 눌러 상세 패널로 가거나 **퇴근** 버튼(확인 창에서 한 번 더 확인)으로 세션을 끝낼 수 있습니다. 사무실은 픽셀이 고르게 보이도록 2배·3배처럼 정수배로 확대해 그립니다(최소 2배). 창보다 크면 페이지를 스크롤해서 봅니다. 로비 카운터의 로봇은 상주 안내원으로, 세션과 무관한 장식입니다(누가 들어오면 손을 흔듭니다). 사무실 위 오른쪽의 **모델 안내** 버튼을 누르면 모델별 품종·직급·모니터와 현재 인원을 보여주고, 모델마다 품종을 고를 수 있습니다.

## 여러 사무실

세션은 작업 폴더의 git 저장소별로 다른 사무실에 출근합니다. 워크트리는 원본 저장소와 같은 사무실이고, 저장소 밖에서 일하는 세션은 기본 사무실("사무실")로 갑니다. 처음 보는 저장소면 기본 배치로 사무실이 새로 생기고, 사무실이 둘 이상이면 화면 위에 탭이 나타나 인원 수와 상태(초록: 일하는 중, 노랑: 응답 대기)를 보여줍니다. 직원 목록에는 모든 사무실의 직원이 나오고, 다른 사무실 직원을 누르면 그 사무실로 넘어갑니다. 사무실과 책상 배정은 `~/.pawgents-office/state.json`에 저장됩니다.

아래쪽 활동 티커에는 보고 있는 사무실 직원의 활동만 나옵니다. 저장소와 상관없이 한곳에서 일하게 하려면 탭 오른쪽의 **이 사무실에 모두 모이기**를 누릅니다. 모든 세션(새로 오는 세션 포함)이 지금 보고 있는 사무실로 모이고 티커도 함께 보여주며, **저장소별로 나누기**를 누르면 각자의 사무실로 돌아갑니다. 이 설정도 서버를 재시작해도 유지됩니다.

### 배치 편집

사무실 위 오른쪽의 **배치 편집** 버튼을 누르면 지금 보고 있는 사무실의 배치를 바꿀 수 있습니다(편집 중에는 고양이가 잠시 숨습니다).

- **방**: 팔레트에서 종류(회의실·로비·라운지·기획실·서재·놀이터·사무 공간)를 고르고 사무실 위에서 끌어 그립니다. 벽은 방 둘레에 저절로 서고(회의실은 유리벽, 놀이터도 벽이 섭니다. 예전에 저장한 배치의 놀이터는 벽 없이 남으니 선택 상자에서 벽을 켜세요), 문 하나가 함께 생깁니다. 방 안쪽을 끌면 안의 가구와 함께 옮겨지고, 선택한 방의 모서리를 끌면 크기가 바뀝니다. 벽 칸을 누르면 문 → 열린 통로 → 벽 순으로 바뀝니다. 선택 상자에서 이름·종류·벽·유리벽을 고칠 수 있고, 어떤 방이든 벽을 넣거나 뺄 수 있습니다. **모든 방 벽 넣기 / 빼기**는 모든 방을 한 번에 바꿉니다(벽이 새로 선 방에 문이 없으면 문 하나가 생깁니다).
- **가구**: 팔레트에서 고르고 놓을 곳을 누릅니다(Esc·우클릭으로 그만 놓기). 끌어서 옮기고, Delete로 지우고, 방향키로 한 칸씩 움직입니다. 책상·회의 테이블·소파·책장·화이트보드·놀이 가구를 놓으면 그 앞에 고양이 자리가 생깁니다. 창문과 간판은 위쪽 벽에 겁니다.
- **사무실**: 이름, 가로·세로 칸 수(20×14 – 64×40), 정문 벽(위·아래·왼쪽·오른쪽)과 위치를 바꿀 수 있습니다. 바깥벽을 누르면 정문이 그리로 옮겨 가고, 정문을 끌어 벽을 따라 옮길 수도 있습니다. 위쪽 벽의 정문은 창문·간판과 겹칠 수 없습니다.
- **공유**: **파일로 내보내기**는 배치를 JSON 파일로 저장하고, **복사**는 같은 내용을 클립보드에 담습니다(메신저 등으로 보내기). 받은 배치는 **파일 가져오기**나 편집 중 Ctrl+V 붙여넣기로 불러오고, **다른 사무실 배치 가져오기**로 다른 사무실의 배치를 그대로 가져올 수도 있습니다. 불러온 배치도 검사를 거치고, 저장해야 반영됩니다.

바꿀 때마다 검사해서 겹치는 곳, 방 밖으로 나간 가구, 문 없는 방, 정문에서 갈 수 없는 자리를 빨간 칸과 목록으로 보여주고, 문제가 있으면 저장할 수 없습니다. Ctrl+Z로 되돌리고, **기본 배치로**는 처음 배치를 불러오고, **모두 지우기**는 방과 가구를 전부 치워 빈 바닥에서 새로 짤 수 있게 합니다(둘 다 저장해야 반영). 빈 사무실은 로비와 책상이 하나씩은 있어야 저장됩니다. 저장하면 열려 있는 모든 화면에 바로 반영되고, 책상이 모자라면 남는 직원은 로비에서 기다립니다. **사무실 닫기**는 그 사무실의 저장소와 직원을 기본 사무실로 보냅니다(기본 사무실은 닫을 수 없습니다).

## 상태 (툴 → 모니터·소품)

| 상태 | 트리거 | 연출 |
|---|---|---|
| 대기 | Stop, idle 알림 | 책상의 커피 → 잠시 뒤 놀이터·휴게실로 |
| 생각 중 | 프롬프트 제출, 툴 완료 직후 | 머리 위 `...` |
| 읽는 중 | Read / Grep / Glob | 책, 어두운 모니터 |
| 코딩 중 | Edit / Write / MultiEdit / NotebookEdit | 파란 모니터 + 코드 줄 |
| 터미널 | Bash | 검은 모니터 + 초록 글자 |
| 검색 중 | WebFetch / WebSearch | 돋보기 |
| 위임 중 | Agent / Task | 전화기, 종이비행기가 보조 직원에게 날아감 |
| 작업 중 | 그 외 툴, 또는 레지스트리 busy | 흰 모니터 |
| 응답 대기 | PermissionRequest, permission 알림, AskUserQuestion | 손 들기 + `!` |
| 퇴근 | SessionEnd, 프로세스 종료 | 문으로 걸어 나감, 5분 뒤 책상 반납 |

| 작업한 파일 | 세션 워크트리의 `git status`(수정·추가·삭제·새 파일)와 이 세션의 툴이 읽거나 고친 파일(훅)을 합친 목록. git 쪽은 서버를 재시작해도 남고 셸이나 손으로 바꾼 파일도 잡으며, 편집·셸 툴이 끝날 때와 패널을 열 때, 그리고 15초마다 갱신됩니다. 같은 워크트리에서 일하는 다른 세션의 변경도 같이 보입니다 |
| 작업한 파일 클릭 | 그 파일의 git diff(작업 트리 vs HEAD). 아직 git에 없는 새 파일은 전체가 추가로, 세션 중에 이미 커밋했으면 그 커밋의 변경이 보입니다. 세션이 그 파일을 다시 고치면 열린 창이 갱신됩니다. 서브에이전트나 셸 명령으로 바꾼 내용도 git이 보는 대로 나옵니다 (git 저장소 밖이면 안내만) |
| 직원 목록 ("목록 ▾") | 모든 사무실 직원의 상태와 위치(자리·회의실·기획 보드·서가·놀이터·로비 등) |
| 화면 하단 활동 기록 | 모든 세션의 툴 사용·지시·답변이 최신순으로 쌓임. 스크롤하면 최근 500건까지 볼 수 있음 |

`hooks/send.ts`는 `tool_response`의 앞 400자만 남기고 버리며, Agent 툴의 지시문은 600자까지 보조 직원에게 연결합니다. 생각 중 내용과 비용은 transcript에서 읽습니다(thinking 블록, `cost-state`).

## 웹에서 지시하기

세션을 웹에서 직접 부리는 방법은 둘입니다. [Orca](https://github.com/stablyai/orca) 터미널에서 실행 중인 세션에 지시하거나, Orca 없이 서버가 `claude -p`로 세션을 직접 띄웁니다. `+ 새 직원`에서 고르며, 둘 다 쓸 수 있으면 **실행 방식**(Orca / 직접 실행) 라디오가 나오고 하나만 가능하면 그쪽으로 정해집니다. `PAWGENTS_OFFICE_BACKEND`로 고정할 수도 있습니다(설정 참고).

### Orca 터미널

`orca` CLI가 PATH에 있어야 합니다.

- **기존 직원에게 지시**: 직원을 클릭하고 패널 아래 입력창에 쓰고 Enter를 누릅니다(Shift+Enter는 줄바꿈). 서버가 `orca terminal send`로 그 세션의 터미널에 입력합니다. 직접 타이핑한 것과 똑같이 처리되고, 작업 중이면 Claude Code가 큐에 넣습니다.
- **새 직원 채용**: 사무실 위 오른쪽의 `+ 새 직원` 버튼을 누르고 실행 방식(Orca), 워크트리, 인원(1–5명), 모델(선택), 첫 지시(선택)를 고르면 `orca agent launch --agent claude`로 새 세션을 띄웁니다. **새 워크트리 만들기**를 켜면 고른 워크트리의 브랜치에서 분기한 새 워크트리(이름이 브랜치 이름이 됨)에서 시작합니다. 곧 로비로 들어옵니다.
- **퇴근시키기**: 패널 머리의 `퇴근`을 누르고 확인 창에서 `퇴근`을 고릅니다. 확인 창의 "다음부터 묻지 않기"를 체크하면 이 브라우저에서는 더 묻지 않습니다(정상 종료와 강제 종료는 따로 기억합니다). 대기 중인 세션은 `/exit`로 깔끔하게 끝납니다. 웹에서 띄운 세션이면 탭도 닫히고, 직접 연 탭이면 셸이 남습니다. 작업 중이거나 권한 응답 대기 중이면 확인 버튼이 `강제 종료`로 바뀌고, Orca 터미널 탭을 닫아 진행 중인 작업을 끊습니다. 대화는 `claude --resume <세션 ID>`로 이어갈 수 있습니다.
- **권한 모드 바꾸기**: 패널 입력창 아래의 모드 선택 상자에서 고릅니다. 화면 하단 상태 줄(`⏵⏵ accept edits on` 등)을 읽어 원하는 모드가 나올 때까지 Shift+Tab을 보냅니다. Shift+Tab으로 닿지 않는 `dontAsk`와 `bypass`는 세션이 이미 그 모드가 아니면 목록에 나오지 않습니다(`claude --permission-mode dontAsk`, `--dangerously-skip-permissions`로 시작해야 합니다). 그 밖에 순환에 없는 모드는 거절되고, 권한·질문 응답 대기 중에는 다이얼로그에 들어갈 수 있어 막혀 있습니다.
- 권한 승인이나 질문 응답을 기다리는 세션에는 지시를 보내지 않습니다. 보낸 Enter가 다이얼로그의 기본 선택(승인)으로 들어갈 수 있기 때문입니다. 터미널에서 먼저 답해 주세요. 그동안 패널에는 무엇을 묻는지(도구·대상·명령)와 ✋ **허용**·**거부** 버튼이 뜹니다. 버튼은 터미널 화면을 읽어 선택지가 정확히 `Yes`(이번 한 번만)이거나 `No`로 시작하는 줄의 번호를 찾고, 그 숫자 키를 눌러 줍니다(번호는 도구마다 다릅니다). "항상 허용" 같은 선택지는 누르지 않습니다. 화면에서 그런 선택지를 찾지 못하거나, 카드가 뜬 뒤 요청이 바뀌었거나, 질문(`AskUserQuestion`) 다이얼로그이면 키를 보내지 않고 거절하니 터미널에서 직접 답해 주세요. 거부나 Esc로 닫으면 훅이 오지 않으므로, Claude Code가 세션 파일(`~/.claude/sessions/<pid>.json`)에 쓰는 상태로 다이얼로그가 닫힌 것을 알아채고 몇 초 안에 대기를 풉니다.

세션과 터미널은 훅이 보내는 `ORCA_TERMINAL_HANDLE`로 연결합니다(Orca가 관리 터미널에 넣어 주는 변수). 훅이 아직 안 온 세션은 같은 워크트리의 claude 터미널이 하나뿐일 때만 자동으로 짝을 짓습니다. 후보가 여럿이면 그 세션에서 한 번 프롬프트를 보내 연결하세요.

### Orca 없이 쓰기 (claude -p)

서버가 세션마다 작은 중계 프로세스(러너)를 띄우고, 러너가 `claude -p --input-format stream-json --output-format stream-json`을 소유합니다. 사용자의 Claude Code 로그인을 그대로 쓰므로 추가 비용이 없고 npm 의존성도 없습니다. `claude` CLI가 PATH에 있어야 합니다(없으면 `PAWGENTS_OFFICE_CLAUDE_BIN`).

- **새 직원 채용**: `+ 새 직원`에서 **직접 실행 (claude -p)** 을 고릅니다(실행 방식 라디오는 Orca와 둘 다 쓸 수 있을 때만 보입니다).
  - **작업 폴더**: 서버가 아는 레포(사무실에 등록된 레포와 살아 있는 세션의 레포)의 git 워크트리 목록에서 고르거나 `직접 입력…`으로 절대 경로를 씁니다.
  - **권한 모드**: `기본`(`default`)은 도구를 쓸 때마다 사무실에서 승인하고, `편집 자동 승인`(`acceptEdits`)은 파일 편집을 묻지 않고, `자동`(`auto`)은 분류기가 판단해 대부분 묻지 않습니다.
  - **새 워크트리 만들기**: 고른 폴더의 레포에 `<레포>-<이름>` 폴더로 워크트리를 만들고, 같은 이름의 브랜치를 새로 땁니다. 같은 사무실로 출근합니다.
  - 인원(1–5명), 모델(선택), 첫 지시(선택)는 Orca와 같습니다.
- **권한 모드 바꾸기**: 패널 입력창 아래 선택 상자에서 고르면 실행 중인 claude에 바로 적용됩니다(stream-json `set_permission_mode`). 작업 중에도 바꿀 수 있습니다. `bypassPermissions`는 `--dangerously-skip-permissions`로 시작한 세션만 가능해 거절됩니다.
- **지시**: 패널 입력창에 쓰고 Enter. 작업 중이거나 권한 응답을 기다리는 중에도 보낼 수 있고, 보낸 지시는 큐에 들어가 다음 턴이 됩니다.
- **권한 승인**: `default` 모드에서 Claude가 승인이 필요한 도구를 쓰면 고양이가 손을 들고 패널에 ✋ 카드(도구·대상·상세)가 뜹니다. **허용**이나 **거부**를 누르면 되고, 30분 안에 답이 없으면 거부로 처리합니다. 동시에 여러 건이 오면 카드도 여러 장입니다. `acceptEdits`/`auto`는 그만큼 덜 묻습니다. 헤드리스에서는 `AskUserQuestion` 도구가 꺼져 있어 질문 다이얼로그는 없습니다.
- **퇴근시키기**: 패널의 `퇴근`을 누르고 확인 창에서 확인합니다. 정상 종료는 입력을 닫아 현재 턴을 마치고 끝내며 `SessionEnd`가 실행됩니다. 작업 중이면 확인 버튼이 `강제 종료`로 바뀌고, 대기 중인 권한 요청을 모두 거부한 뒤 프로세스 트리를 끝냅니다.
- **서버를 꺼도 세션은 삽니다**: 러너는 서버와 분리돼 `~/.pawgents-office/run/<세션 ID>.json`과 명명 파이프(Windows) 또는 `.sock`(POSIX)로 남아 있다가, 서버가 다시 뜨면 재연결합니다(서버 로그 `headless restored: N`). 서버가 꺼진 동안 권한 요청이 오면 훅이 서버를 자동으로 띄웁니다(`PAWGENTS_OFFICE_AUTOSTART=0`이면 띄우지 않고 거부로 처리).
- **터미널에서 이어가기**: `claude --resume <세션 ID>`. `-p` 세션은 `--continue`나 선택 목록에는 안 보입니다.

결정용 훅은 `~/.pawgents-office/headless-settings.json`을 `--settings`로 넘겨 이 방식으로 띄운 세션에만 붙습니다. 터미널에서 직접 연 세션과 플러그인 훅은 그대로입니다. 다른 플러그인의 `PermissionRequest` 훅이 먼저 결정하면 그 결정을 따릅니다.

#### 문제 해결

- **`직접 실행 시작 실패: Not logged in`**: 터미널에서 `claude`를 한 번 실행해 로그인하세요.
- **`~/.pawgents-office/run/`에 파일이 남아 있음**: 러너가 죽은 흔적입니다. 서버가 시작할 때 정리합니다.
- **POSIX에서 `.sock`을 못 만듦**: `PAWGENTS_OFFICE_DATA` 경로가 아주 길면 소켓 경로 한도(약 100자)에 걸립니다. 더 짧은 경로를 쓰세요.
- **Windows에서 서버가 러너에 못 붙음**: 명명 파이프는 같은 사용자 로그온 세션에서만 접근할 수 있습니다.

터미널에 입력을 넣거나 세션을 띄우는 엔드포인트(`POST /sessions/:id/prompt`, `POST /sessions/:id/close`, `POST /launch`)와 권한 응답(`POST /sessions/:id/permission`)은 같은 출처의 JSON 요청만 받습니다(Host·Origin·Content-Type 검사). 다른 웹페이지가 지시나 승인을 몰래 보낼 수 없고, `/hook`도 브라우저 요청(Origin 헤더 있음)은 거부합니다. 파일 내용이 통째로 나가는 `GET /sessions/:id/diff`는 Host를 검사하고, 그 세션의 툴이 실제로 연 파일만 보여줍니다.

## 모델별 외형 (직급)

직원은 모두 고양이(보조 직원은 새끼 고양이)입니다. 이동할 때는 네 발로 뛰어다니고, 자리에서는 앉아서 앞발로 키보드를 두드리거나 책을 펼칩니다. 고양이 품종, 책상 장비, 직함은 세션이 쓰는 모델 계열에 따라 정해집니다. 기본 품종은 '똑똑한 고양이' 순위에 자주 오르는 순서를 따랐고, 사무실 위 오른쪽 **모델 안내**에서 모델마다 품종을 바꿀 수 있습니다(서버의 `state.json`에 저장되어 모든 브라우저에 바로 반영). 고를 수 있는 품종: 아비시니안, 샴, 러시안블루, 페르시안, 코숏, 벵갈, 랙돌, 메인쿤, 브리티시 숏헤어, 스핑크스, 노르웨이 숲, 봄베이, 터키시 앙고라, 스코티시 폴드, 먼치킨. 품종마다 털색뿐 아니라 체형도 다릅니다(큰 귀·작은 귀·접힌 귀·링크스 귀털, 날씬·통통·대형·짧은 다리).

| 모델 | 직함 | 기본 품종 |
|---|---|---|
| Fable | 수석 | 아비시니안 (붉은 갈색 틱드 털) |
| Opus | 선임 | 샴 (크림색 몸, 어두운 얼굴·귀·발·꼬리, 파란 눈) |
| Sonnet | 사원 | 러시안 블루 (청회색, 초록 눈) |
| Haiku | 인턴 | 페르시안 (긴 털, 볼 갈기) |
| 기타 | — | 코리안 숏헤어 (치즈·고등어·턱시도·올블랙·삼색) |

같은 품종 안에서도 세션마다 털색이 조금씩 다릅니다(예: 샴은 실·블루·라일락 포인트).

| 계열 | 모델 id 패턴 | 직함 | 외형 | 책상 |
|---|---|---|---|---|
| Fable | `fable`, `mythos` | 수석 | 보라 정장 + 금색 넥타이 + 금 배지 | 금테 와이드 모니터 |
| Opus | `opus` | 선임 | 남색 정장 + 빨간 넥타이 + 안경 | 은테 모니터 |
| Sonnet | `sonnet` | 사원 | 청록 캐주얼 + 헤드폰 | 일반 모니터 |
| Haiku | `haiku` | 인턴 | 주황 티셔츠 + 사원증 목걸이 | 작은 노트북 |
| 기타 | 그 외 / 미확인 | — | 세션 해시 색, 액세서리 없음 | 일반 모니터 |

모델은 `SessionStart` 훅의 `model`, `PostModelSwitch`, transcript의 assistant 메시지에서 읽습니다. 보조 직원은 자기 transcript의 모델을 쓰고, 없으면 부모 세션 모델을 따릅니다. 계열·직함·액세서리 정의는 `web/sprites/data.ts`의 `FAMILIES` 한 곳에 있습니다.

### 스킨 (직접 그린 스프라이트)

**모델 안내** 아래쪽 **스킨**에서 PNG 스프라이트 시트를 올리면, 모델마다 품종 대신 그 그림을 고를 수 있습니다(품종 선택 목록의 "내 스킨"). 보조 직원은 같은 스킨을 작게 그립니다. 안내원은 그대로 로봇입니다.

- **시트 규격**: 크기가 같은 칸으로 나눈 격자입니다. 한 줄이 동작 하나이고, 왼쪽부터 칸마다 프레임 하나를 그립니다. 줄 안에서 빈(완전 투명) 칸이 나오면 그 줄은 거기서 끝납니다. 칸 크기는 올릴 때 정하고(4–64px), 최대 12줄·16칸, 512KB까지 올릴 수 있습니다.
- **줄 순서**: ① 앉아 있기(정면) ② 걷기(오른쪽을 보고, 왼쪽으로 갈 때는 뒤집어 그림) ③ 타이핑 ④ 책 읽기 ⑤ 손 들기 ⑥ 전화 ⑦ 화이트보드에 쓰기 ⑧ 엎드리기(라운지·낮잠) ⑨ 뒷모습(회의 테이블·책상) ⑩ 옆으로 앉기(오른쪽을 보고) ⑪ 스크래처 긁기 ⑫ 털실 치기. ①②는 꼭 있어야 하고, 나머지는 비워 두면 비슷한 동작으로 대신합니다(전화·쓰기 → 손 들기, 뒷모습·옆모습 → 그 자리의 정면 동작, 그 밖에는 앉아 있기).
- **크기**: 시트 전체에서 그림이 있는 영역으로 잘라서, 그 높이가 24px(사무실 1.5칸) 이하면 그린 크기 그대로 그립니다. 더 크면 고해상도 그림으로 보고 2배·3배처럼 정수배로 줄여 그립니다(48px 칸에 그리면 크기는 같고 화면 2배에서 두 배 세밀하게 보입니다). 보조 직원은 그 3/4 크기입니다. 32px 칸에 크게 그려도 화면에서는 세밀하게 보입니다. 발은 칸 아래쪽에 맞추세요.
- **템플릿 내려받기**: 지금 고양이가 위 줄 순서대로 24×24 칸에 그려진 PNG를 받습니다. 그 위에 덧그리면 그대로 맞습니다.
- 올리기 전에 줄마다 잘린 프레임을 미리 보여 줍니다. 스킨은 `~/.pawgents-office/skins/<id>.png`에 저장되고, 이름과 칸 크기는 `state.json`에 기록됩니다. 스킨을 삭제하면 그 스킨을 쓰던 모델은 기본 품종으로 돌아갑니다.

## 설정

| 환경변수 | 기본값 | 설명 |
|---|---|---|
| `PAWGENTS_OFFICE_PORT` | `17777` | 서버 포트. 훅 스크립트도 같은 변수를 읽습니다. |
| `PAWGENTS_OFFICE_DATA` | `~/.pawgents-office` | 사무실·배치·책상 배정·품종 설정(`state.json`), 스킨(`skins/`)과 서버 로그 저장 위치 |
| `PAWGENTS_OFFICE_DEBUG` | | `1`이면 훅 스크립트가 `~/.pawgents-office/hook.log`에 기록 |
| `CLAUDE_CONFIG_DIR` | `~/.claude` | Claude Code 설정 디렉터리를 옮긴 경우 |
| `PAWGENTS_OFFICE_BACKEND` | `auto` | 새 직원을 띄우는 방식. `auto`는 쓸 수 있는 쪽을 모두 보여주고, `orca` / `headless`로 고정할 수 있습니다. |
| `PAWGENTS_OFFICE_CLAUDE_BIN` | `claude` | 직접 실행(`claude -p`)이 쓰는 claude 실행 파일. PATH에 없을 때 경로를 지정합니다. |
| `PAWGENTS_OFFICE_ORCA_BIN` | `orca.exe` (Windows) / `orca` (macOS) / `orca-ide` (Linux) | Orca CLI 실행 파일. `ORCA_CLI_COMMAND`가 있으면 그 값을 씁니다. |

## 트러블슈팅

- **직원이 안 나타남**: 플러그인이 켜져 있는지(`/plugin`) 또는 `bun run install-hooks`를 실행했는지, 서버가 떠 있는지 확인. 이미 떠 있던 `claude`는 재시작해야 툴 상세가 보입니다(존재 여부는 레지스트리로 바로 보임).
- **훅이 도는지 확인**: `PAWGENTS_OFFICE_DEBUG=1 claude` 로 실행한 뒤 `~/.pawgents-office/hook.log`를 보거나, `claude --debug hooks`.
- **서버 로그**: 서버 터미널에 `[hook] PreToolUse Edit · office.ts  <세션> → coding` 식으로 찍힙니다.
- **포트 충돌**: `PAWGENTS_OFFICE_PORT=18000 bun run start` 처럼 바꾸고, 훅도 같은 변수를 보도록 쉘 환경에 export 하세요.

## 구조

의존은 한 방향입니다: `shared/` ← `server/`·`hooks/`·`scripts/`·`web/`. `web/`는 브라우저에서 쓸 수 있는 `shared/`만, `shared/`는 자기 자신만 import 합니다(`test/boundaries.test.ts`가 검사).
서버 안에서는 `domain/`(순수 규칙) ← `store/`·`app/`(유스케이스) ← `http/`·`backends/`·`infra/`(입출력) ← `main.ts`(조립) 순입니다.
